# Blog process

Write from one reader problem to one durable insight. Code and claims must be
verified against the package version the article presents.

## Workflow

1. Define the reader, their starting model, and the change in understanding.
2. State one thesis and choose the smallest narrative that proves it.
3. Gather primary sources and executable examples before drafting.
4. Explain the problem and constraints before introducing the Institute
   abstraction.
5. Keep examples minimal, compilable, and consistent with current public API.
6. Review separately for technical truth, pedagogy, voice, and launch claims.
7. Verify links, code, metadata, and downstream calls to action.
8. Treat publication or deployment as a separately authorized action.
